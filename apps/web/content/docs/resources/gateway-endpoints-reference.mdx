The desktop gateway binds to `127.0.0.1:19432` (or the first fallback in `19433–19435`). All `/api/gateway/*` routes require auth.

## Metadata

| Route | Methods | Notes |
|---|---|---|
| `/health` | GET | Unauthenticated liveness and capability probe. |
| `/api/gateway/repos` | GET, POST, DELETE, PATCH | Managed repositories. |
| `/api/gateway/settings/binary-paths` | GET, PATCH | Override claude/codex/python3/git paths. |
| `/api/gateway/mcp-auth` | GET | MCP auth metadata parity route. |

### Retired: local-`gh` PR data and identity routes

These answered from a local `gh` invocation and are retired. Desktop GitHub data
now comes from the cloud projection or server-backed GitHub APIs, so the routes
stay registered and, once a request passes the gateway's auth, onboarding and
approval gates, respond **HTTP 410** with
`{ "error": "github_data_route_retired" }`. Those gates run first and can answer
before the route does — a request made before onboarding completes gets 403, not
410.

410 rather than an unregistered path so a version-skewed client can tell a
deliberately removed endpoint from one that is merely unimplemented: this gateway
answers 501 `operation not implemented` for an unrecognized `/api/gateway/*`
path, which means "may arrive later".

## Operation IDs

The supported operation IDs drive approval policy and telemetry tagging:

```
git_action, git_pr, git_branch_worktree,
repos_config, filesystem, binary_paths_settings
```

## Required headers for authenticated calls

- `X-Desktop-Gateway-Token` (internal cloud executor) **or** `X-Desktop-Session-Token` + `Origin` (browser)
- `Content-Type: application/json` (where a body is sent)

See [Desktop gateway](../mechanisms/desktop-gateway) for the full auth model.
