          Search across the organization. Provide `q` (a free-text query, 2–200
          characters), or `tagId` (a tag UUID) to scope results to items
          carrying that tag. `q` is required unless `tagId` is supplied. The two
          are **not** mutually exclusive: sending both is accepted, and `tagId`
          wins — the tag branch runs and `q` is ignored without being validated,
          so a `q` that would otherwise be rejected as too short or too long
          still succeeds alongside a `tagId`. When `tagId` is supplied,
          `tagId`/`tagName` are echoed on the response. Requires the `read`
          scope.


          This endpoint returns **one of two response shapes**, and the request
          selects which:


          - **Documents-and-projects search** (`GlobalSearchResponse`) — a
          substring search over documents and projects. This is the shape you
          get for a plain `?q=…` or `?tagId=…` request.

          - **Unified search** (`UnifiedSearchResponse`) — a heterogeneous
          ranked list over the whole corpus (documents, projects, loops,
          sessions, branches, pull requests, comments, agent components; session
          transcripts match only for an organization opted into transcript
          search). The response carries `results`/`nextCursor` instead of
          `documents`/`projects`.


          `tagId` takes precedence over everything below: a request carrying a
          **non-empty** `tagId` always returns `GlobalSearchResponse`, and any
          unified param sent alongside it is ignored (`?tagId=<uuid>&cursor=…`
          does **not** page). The value is trimmed first, so an empty or
          whitespace-only `tagId` (`?tagId=`, `?tagId=%20`) is treated as absent
          rather than validated — it does not take precedence and it is not
          rejected as a malformed UUID; the request falls through to the `q`
          path (`?tagId=&mode=prefix&q=auth` returns `UnifiedSearchResponse`,
          and `?tagId=` on its own is a 400 `q is required`). Otherwise the
          unified shape is returned when **either** of these holds, so a client
          that only handles `GlobalSearchResponse` must avoid both:


          1. Any of `mode`, `types`, `since`, `until`, or `cursor` is present on
          the request (`limit` alone does not switch shapes).

          2. `q` carries an inline query-language filter that the parser ACCEPTS
          — an `@owner` mention, or a
          `type:`/`status:`/`priority:`/`project:`/`updated:` token with a valid
          value (e.g. `?q=auth type:loop`). A filter the parser rejects
          (`?q=auth type:widget`) is not applied and does not switch shapes, and
          neither does an unknown key (`?q=auth foo:bar`), which is just free
          text. A bare `q` with no filter token keeps the documents-and-projects
          shape.


          **Exact ID/slug hits bypass the filters.** On the unified path, the
          first bare `q` token that looks like an entity UUID or slug (`FEA-42`)
          is lifted out of the free text and resolved by a separate exact-lookup
          query, whose match is prepended to `results` ahead of the ranked
          full-text hits (de-duplicated if the same record also matched the text
          scan). That lane is scoped by organization and by `types` only.
          `since`, `until`, and the inline
          `@owner`/`project:`/`status:`/`priority:`/`updated:` predicates are
          applied to the full-text lane alone and are **not** applied to it — so
          an exact hit can be returned even when it falls outside the requested
          date window or filter set, including when those filters match nothing
          else. Exact hits are emitted on the first page only (no `cursor`); on
          later pages the record is excluded from the full-text scan rather than
          repeated. Every hit is re-authorized individually regardless of lane,
          so this never widens what a caller may see.
