          Breaks the organization's agent sessions down by tool, agent type,
          repository, and project. Accepts the same filters as `GET
          /agent-sessions`, with one deliberate difference: the date window here
          is a session START window on the session's start time, not the list's
          and usage summary's `lastActivityAt` activity window — so the same
          `startDate`/`endDate` can match a different set of sessions than the
          list does. This read has NO server-side population cap, and no `limit`
          parameter to supply — the query schema is strict, so a caller cannot
          voluntarily bound the population even if they want to. With no
          `startDate`/`endDate` it pages every session in the organization into
          memory, holding two full accumulations of the result at once, and each
          matched session's event stream is itself fetched unbounded — unlike
          the single-session detail read, which caps events at 10,000. The
          failure mode is MEMORY, not latency: a large enough request can
          exhaust the API process's heap and fail the request outright rather
          than merely running slowly, and a request timeout does not bound it.
          Always send a `startDate`/`endDate` window. Requires the `read` scope.
