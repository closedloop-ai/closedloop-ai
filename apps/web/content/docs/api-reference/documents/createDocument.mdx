      - content: >-
          Requires an API key with `write` scope. Creates a new document. The
          `type` field determines what kind of artifact is created: **PRD**
          captures product requirements, **IMPLEMENTATION_PLAN** is a detailed
          plan typically produced from a PRD, **FEATURE** captures a feature
          specification, **TEMPLATE** is a reusable document template, and
          **DOC** is an evergreen document. The `type` field also accepts the
          **ISSUE** alias, which is treated as **FEATURE** (the product's
          "Issue" is a rename of Feature). Whether the document lives inside a
          project depends on its `type`: the project-bound subtypes (**PRD**,
          **IMPLEMENTATION_PLAN**, **FEATURE**, and its **ISSUE** alias)
          **require** a `projectId`, while the organization-level types
          (**DOC**, **TEMPLATE**) are created at the org level and must **omit**
          `projectId` — supplying one for a **DOC** or **TEMPLATE** is rejected
          with a 400. Provide initial `content` as a string (Markdown or plain
          text). The document is versioned automatically — each subsequent
          update creates a new version while preserving history. To link the new
          document to a parent PRD (for example, creating a plan that was
          produced by a PRD), pass the parent's ID as `sourceId`; the platform
          will create a PRODUCES artifact link automatically.
