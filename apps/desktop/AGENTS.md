# Desktop App Guidelines

## Ownership

`apps/desktop` is the source-owned Closedloop Desktop/Electron client inside the `symphony-alpha` monorepo. Do not treat `closedloop-ai/closedloop-electron` as an active implementation or release owner; references to that repository must be explicitly historical.

End-user-perceivable UI changes must ship behind a flag, default off — see root AGENTS.md + the `ui-feature-flag-attestation` gate. On desktop the gate is a Labs config toggle; when the surface is shared with web, keep it gated on both (PostHog on web, Labs here) so it can't leak on one while hidden on the other. Renderer-only work with no web analogue needs the Labs toggle alone — do not invent a PostHog flag for a surface `apps/app` does not have.

## Versioning And Build Info

**Do NOT bump the `version` field in `apps/desktop/package.json` as part of your change.** `desktop-version-bump.yml` mints the next `desktop-v<patch>` tag on merge to `main` whenever the `apps/desktop` build closure changed (turbo `[before...sha]` filter, FEA-2135), and the next version is `max(highest ledger patch in the series + 1, manifest patch)` (FEA-2156) — so the manifest patch is a **FLOOR**. Raise it only to deliberately jump a release or advance the `major.minor` series, and only when the task asks; revert any incidental patch bump. Enforced by `desktop-version-guard.yml`. **Release Desktop** publishes the commit the highest reachable `desktop-v*` tag points at (`scripts/deploy/read-desktop-version.ts`), so released numbers may skip.

`src/shared/build-info.ts` is generated by `pnpm -C apps/desktop prebuild` and must not be committed. Run that prebuild before Desktop lint, typecheck, source assertions, or tests that load app entrypoints. Main process output is JS-only under `dist/`; do not commit generated `dist`, `.generated`, package-stage, or DMG output.

### Never write `import` next to a quote in main-process source (ISS-6068)

In every module the electron-vite `main` build bundles, **never follow the bare word `import` with a quote or an apostrophe inside a comment or a string.** The possessive is how it gets written — `the last import's verdict`, `this import's wall clock` — and a quoted noun does it too: `a "large import"`. Reword instead: `the collector import, whose …`, `a large import pass`. Enforced by the `no-esm-shim-import-quote` source gate (`pnpm check:source-gates`), whose failure message carries the contract and the remedy.

This is a prose rule only because electron-vite makes it a build rule. Its `vite:esm-shim` plugin appends a CommonJS shim to the emitted `format: "es"` main chunk, and picks the insertion point by regex-scanning the **rendered chunk text** for the last ESM static import. That regex does not skip comments or strings, and its import clause is optional, so a bare `import` followed by a quote opens a bogus match that runs to the next quote **anywhere later in the chunk** — across statements, across modules. If that match is the last one, the shim lands where it ends; mid-expression, the build dies with an error naming neither the file nor the cause (`startup-*.js:37701:7: ERROR: Expected ":" but found "__cjs_mod__"`).

Two properties make it worth a written rule rather than review judgement. It is **invisible to every fast LOCAL signal** — lint, typecheck, and `pnpm -C apps/desktop test` all pass, because that script is `test:preflight && test:node && test:renderer` and none of the three bundles; only `pnpm -C apps/desktop build:main` sees it. CI is not exposed the same way: `desktop-build`, `desktop-node` and `desktop-renderer` each run `pnpm --filter desktop run build` before their suites, so this class cannot reach `main` through a green PR. The gap the gate closes is the local one, and it closes it in milliseconds on the always-on lint lane with a message that names the file and the fix — which is why the desktop test lane does **not** also run the bundle build (ISS-6068 ask 3). And an occurrence that does *not* break the build today is **latent, not safe**: whether its bogus match ends somewhere harmless depends on chunk contents it does not own, so an unrelated edit can break it later. That is why the gate fires on the adjacency rather than on a red build. First diagnosed in PR #4858 (fixed in `d83ab3dc2`); it cost ~50 minutes and required reading the plugin's source.

**What is guarded is a build closure, not a path list, and this file is not its definition.** The gate scopes itself to the electron-vite `main` build closure, which `scripts/lint/rules/desktop-main-build-closure.ts` derives from `electron.vite.config.ts` and walks through value imports. That set reaches past `apps/desktop/src/` into the workspace packages the main chunk inlines from source, and it excludes files that sit under those directories but are reached only by the `preload` build or a type-only import — so neither "everything under `src/main`" nor "desktop only" describes it. Do not restate it here: adding a worker entry or an inlined package widens the gate with no edit anywhere, and a second hand-written copy of the scope is the exact defect the closure replaced. `src/renderer` is outside it, because that builds from `vite.renderer.config.ts` as browser code with no CJS syntax — the shim never runs over it, and UI copy like `"Pause import"` is safe. If you need to know whether one file is in, run the gate rather than reason from a prefix.

## Local Database (SQLite/libSQL + Prisma)

The desktop local store is **SQLite (libSQL)**, not Postgres — every hand-written read/write, aggregate, and migration `.sql` MUST be SQLite dialect. The full rules live in **[`src/main/database/AGENTS.md`](src/main/database/AGENTS.md)** and are required reading before touching any desktop DB code, SQL, or migration: the Postgres→SQLite construct table and analytics-aggregate invariant, the migration runner + immutability contract, the typed `DesktopPrisma` reader/writer topology (`prisma.write`/`prisma.read`/`prisma.client`), and the DB-host `utilityProcess` proxy boundary (never pass a callback through the proxy).

## Desktop→Cloud Sync Lanes

Five independent sync state machines carry locally-captured data to the cloud:
the session-metadata outbox, the invocation-parts outbox, the component-inventory
cursor sweep, the transcript archive ledger, and trace-comment CRUD sync. They
are NOT the same shape. The ten crash-correctness invariants they share, the
recurring cross-lane failure modes, and the KNOWN GAPS where a lane does not
currently satisfy an invariant are all required reading before you touch any of
them or add a sixth: **[`src/main/sync/AGENTS.md`](src/main/sync/AGENTS.md)**.
Do not read those rules as a description of what every lane already does.

## Electron And Gateway Rules

Gateway operations live in `apps/desktop/src/server/operations/` because they need local filesystem and process access. Do not reimplement them in `apps/app` or `apps/api`. Enforced by the `no-desktop-gateway-import` source gate (`pnpm check:source-gates`), which sweeps `apps/app`, `apps/api` and every workspace package on their runtime dependency closure — `packages/app` included — and reports a module load it cannot prove stays outside the tree rather than waving it through.

Binary path discovery is centralized in `src/server/shell-path.ts`. Use `getShellPath()` / `getShellPathSync()` and `resolveBinaryFromLoginShell()` / `resolveBinaryFromLoginShellSync()`; do not add direct `which` calls or shell reimplementations.

When Desktop code uses a resolved shell PATH to decide whether a CLI or harness is available, pass that same resolved PATH into the child process env used for the selected command, or document and test the intentional difference.

Gateway auth must fail closed. Missing Desktop API keys may make local browser gateway mode unavailable with an explicit error, but must not crash app startup, silently fall back to insecure auth, or expose gateway routes by origin alone.

Guard every `webContents.send()` call with `!window.isDestroyed()` and `!window.webContents.isDestroyed()` — Electron objects can throw after sleep/wake or frame disposal. Use `sendToRendererWindow` from `src/main/ipc/renderer-ipc.ts` (or `DesktopWindow.sendToRenderer()` when you have the window object).

Sandbox access is owned by `isPathAllowed()` in `src/server/security.ts` and `buildAllowedDirectories()` in `src/shared/sandbox-policy.ts`. Sensitive directories remain denied even if a parent path is allowed.

## Renderer Rules

Renderer effects that synchronize UI from state or props must include an explicit dependency array matching the intended trigger. Omit the dependency array only when every-render execution is intentional and documented next to the effect.

Overview or dashboard metrics must be backed by aggregate data or by a known-complete collection. Do not present global totals derived from paginated list data unless the label clearly says the metric is page-scoped.

When replacing callback-driven navigation with `href`/`Link` navigation, remove the obsolete callback prop from the wrapper, call site, and public type in the same change.

Renderer code must consume the **full IPC response shape** the main process sends, not a reduced success value: handle both the mismatched-success (`{ ok: true, enabled: false }`) and `{ ok: false, error }` paths, and report what happened rather than what was requested. A transient/retryable marker must survive every boundary it crosses — replacing a client rejection with a generic source error strips it and downstream retry matching never fires.

### E2E Coverage for UI Surfaces (MANDATORY)

E2E coverage for renderer surfaces is part of "done" here, the same way the Parker Protocol design pass is — not a soft suggestion. This extends the repo-wide Test Practices in the root `AGENTS.md` and the desktop `Test Practices` section below; it does not replace the renderer render-tests those rules already require.

- **New UI surface ⇒ new Electron-e2e spec.** Any NEW renderer surface you add under `apps/desktop/src/renderer` — a screen, route, drawer, dialog, panel, tab, or otherwise significant component — ships in the same change with an Electron-e2e spec that exercises its primary flow (launch the app, navigate to it, drive its main interaction, assert the observable result), not just a mounted-in-isolation render test.
- **UI bug fix ⇒ regression e2e.** Any renderer UI BUG FIX adds an e2e test that reproduces the bug through the launched app and would fail without your fix, guarding the regression. Cover the aesthetic/visual dimension too when the bug was visual — assert the corrected rendered state (visible text, layout, empty/error/loading state).
- **Where the tests live and how to run them.** Specs are `apps/desktop/test/e2e/<surface>.spec.ts` and reuse the launch/seed helpers in `apps/desktop/test/e2e/helpers/` (`desktop-app.ts`, `seed.ts`, `seed-branches-db.ts`); Playwright drives the compiled Electron app per `apps/desktop/playwright.config.ts`. Run `pnpm -C apps/desktop prebuild && pnpm -C apps/desktop build`, then `CODEX_HOME="$(mktemp -d)" pnpm -C apps/desktop test:e2e` — the fresh temporary `CODEX_HOME` is not optional (see "Electron E2E: isolate `CODEX_HOME`" below). For pure renderer wiring (a component subscribes to an IPC event or invokes a `window.desktopApi` method), a vitest render test under `src/renderer/**/__tests__/*.test.tsx` run by `pnpm -C apps/desktop test:renderer` is the right slice. These slices need native / a display server, so they are out of the Dagger `dagger call e-2-e` path (web only). Diagnose failures in the `desktop-e2e` lane (the full suite, `.github/workflows/e2e-test.yml`) or `desktop-build` (the targeted Electron subset in `.github/workflows/pr-test.yml`, alongside `desktop-node` and `desktop-renderer`) — never in the `desktop` aggregator, which runs no suite of its own and exists to keep the required-context name.
- **A local run is not a machine takeover** (ISS-5987). Electron has no headless mode — every `--headless` form is silently ignored, do not re-litigate it with a Chromium switch — so `launchDesktopApp` passes the app-level `--e2e-no-reveal` argument, which makes `DesktopWindow`'s final `show()` a no-op while the whole reveal sequence still runs; Playwright's checks are layout/DOM-based, so a never-revealed window drives identically. To WATCH a run use `npx playwright test --debug` (`PWDEBUG=1`, which `windowRevealLaunchArgs` honors from either launcher); plain `--headed` does NOT reveal it, because it only sets `use.headless`, which `_electron.launch` never consults. A spec whose subject IS the reveal opts out with `revealWindow: true` (`startup-window-reveal.spec.ts`). Production reveal behavior is untouched twice over: the argument is absent from every shipped launch, and `isWindowRevealSuppressed` returns false on `options.isPackaged` before it ever reads argv — that second half is the enforced one, so do not delete the `isPackaged` branch.
- **Cross-surface work covers both adapters.** When the surface, workflow, hook, or component is shared through `packages/app` and reused across web and desktop, add coverage on BOTH adapters — the desktop Electron-e2e spec here AND the web `e2e/` Playwright spec described in `apps/app/AGENTS.md` — because behavior can diverge by adapter (routing, feature flags, API origin, Electron vs browser runtime). This is the same both-surfaces expectation stated in the root `AGENTS.md` cross-surface guidance.

Keep third-party notice updates in the root `THIRD_PARTY_NOTICES.md` when bundled upstream packages or parsing references change.

When Desktop merges or deduplicates pull request references for session storage, sync, or dashboard projection, use repository full name plus PR number as the identity when a repository is available. ### `gitBranch` is not attribution data (FEA-2531)

Harness-reported git branch fields — `session.gitBranch` (captured once at session start) and per-line `NormalizedToolUse.gitBranch` — report the branch of the session's CWD checkout. They are wrong for **every** worktree flow (the session sits in the main checkout on `main` while all real work happens through `cd ../worktree && …`) and go stale after any mid-session checkout. Do not use them to attribute branches, PRs, or cost. Attribution must derive from `session_artifact_links` relationships produced by the artifact-ref extractor: write methods (`git_push` / `gh_pr_create` / `git_commit`) carry `relation: "created"`; reads (`start_branch` / `git_checkout` / `git_worktree_add`) stay `workspace` and never attribute. A created PR's head ref resolves evidence-first (gh's own create output / `--head` flag, else the session's nearest preceding branch write); `tu.gitBranch` remains raw CWD context and is never PR-head evidence. Preserve observed branch names; authoritative repository metadata decides product eligibility before branch reads or cost attribution (ISS-5828). When touching branch/PR attribution, trace the change through the extractor dedup, `createdPrHeadBranches`, the `pull_requests` upsert, and the link-propagation passes — not just the emission site.

### Collection-mode mutual exclusivity (FEA-1839)

A harness's live telemetry is captured by exactly one channel at a time: the Closedloop hook handler (`"hooks"`) or the live JSONL file watcher (`"watcher"`) — never both. Running both for one harness double-counts every tool-call and lifecycle row. `getActiveCollectionMode(harness, hooks)` in `src/main/collectors/engine/collection-mode.ts` is the single source of truth for this routing; `CollectorManager` starts a live watcher only for `"watcher"`-mode harnesses (`"hooks"`/`"disabled"` run the idempotent boot import once, no watcher). Every new harness must derive its live-collection decision from this function — do not add an inline hooks-installed conditional at a call site. The `mutual-exclusivity-monitor` records a single `mutual_exclusivity_violation` event row if both channels ever emit the same harness session in one process lifetime.

## Runtime discipline

Harness discrimination must stay closed-set. Match known service or harness identifiers exactly, or by documented namespace prefixes, instead of substring scans over arbitrary metric names, span names, attribute keys, or attribute values. Add a negative test for substring-only false positives when adding a new identifier family.

Optional capture/runtime modules must not crash their owner at import time because a descriptor, parser, or dependency-heavy runtime initialized at module scope failed. Initialize those resources lazily or behind the runtime start/request path, surface failures through the existing unavailable/log path, and keep raw payloads out of diagnostics.

Desktop telemetry relay/export paths are best-effort. OTLP serialization and relay transport dispatch must not throw through runtime export APIs, fail IPC handlers, or block local buffering; wrap serialization/dispatch failures at the exporter boundary and add coverage for the local success path.

Async runtime startup continuations must not restart dependent subsystems after shutdown or supersession. When a `start()` path awaits or attaches a callback before starting collectors, listeners, or sidecars, capture the current start promise or generation and check both the closed flag and that captured identity before mutating runtime state.

Local session source readiness is owned by the SQLite-backed renderer IPC source, not optional capture sidecars. Hook listener, collector, or OTLP startup failures may degrade capture, but they must not make Desktop Sessions unreadable once DB IPC/runtime readiness is established; cover mixed ready-plus-capture-failed states when changing this lifecycle.

In `stop()`/`destroy()` methods, clear ALL accumulated state — Maps, Sets, timestamps, intervals — not just timers; stale values from a previous lifecycle corrupt analytics or behavior on restart.

Distinguish transient failures (network timeout, CLI not found in PATH, gh auth expired) from permanent impossibility (no git directory, file format unsupported). Only set `not_applicable` or permanent failure states for the latter; transient failures should leave retry eligibility intact.

## Release Contract

Desktop releases are owned by `closedloop-ai/symphony-alpha` and use the shared Desktop release contract from `@repo/api/src/types/desktop-release`. Release producers and consumers must use the `desktop-v<version>` tag, `desktop-release.json`, `latest-mac.yml`, and the Desktop-only URL allowlist. Do not use repo-global latest release semantics for Desktop web lookup or packaged updater behavior.

Public first-install distribution (FEA-3372) mirrors the signed DMG to `closedloop-ai/closedloop-ai`, which receives the `.dmg` only — ownership of the release, the updater feed, and `downloadUrl` resolution stays on `closedloop-ai/symphony-alpha`. Public docs must link the rolling `desktop-latest` release's fixed-name `Closedloop-universal.dmg` asset, never `/releases/latest`: a non-desktop release in that repo would otherwise hijack the link and hand people the wrong artifact.

**The rolling `desktop-latest` release deliberately claims repo-global "Latest" on `closedloop-ai/closedloop-ai` (ISS-6007, Mike's explicit call, 2026-08-11).** This is a scoped override of the rule above, which still holds everywhere else — nothing about Desktop *web lookup* or *packaged updater* behavior may read repo-global latest, and the per-version archive releases stay `--latest=false`. The override exists so both permanent first-install URLs resolve to the same fixed-name asset: `/releases/download/desktop-latest/Closedloop-universal.dmg` (unchanged, and still what the public docs link) and `/releases/latest/download/Closedloop-universal.dmg`. The hijack risk that originally motivated the blanket ban is **accepted, not refuted**: that repo is desktop-only today, so nothing competes for the pointer, and the `claim_public_latest` / `verify_public_latest` jobs in `.github/workflows/desktop-release.yml` read the repo-Latest tag back after the claim and fail loudly into Slack (`scripts/deploy/verify-public-latest-release.ts`) if it is not `desktop-latest`. Re-evaluate the override — do not silently revert it — if that repo ever hosts non-desktop releases.

**Know the guard's actual reach before relying on it.** It observes the pointer only while a release run is in flight, so it catches a hijack that already happened by the next release; it is not a continuous monitor, and a non-desktop release that takes repo-global Latest between releases goes unreported until then. Detecting that case needs a check on a release-event or scheduled trigger, independent of promotion — there is none today, so do not describe the pointer as continuously guarded. **Reclaiming the pointer does not need a new version**: the public `desktop-latest` promotion runs on the idempotent skip path too (ISS-6387), so re-dispatching `Release Desktop` for an already-published version re-promotes and re-claims. `gh release edit desktop-latest --repo closedloop-ai/closedloop-ai --latest=true` remains the direct route.

Users on old `closedloop-electron` updater builds do not auto-upgrade across repositories. Active install and upgrade instructions must direct them to manually install the new `symphony-alpha` Desktop release.

## Idempotent Re-Processing: Revision Constants

Desktop uses four version constants to trigger idempotent re-derivation of local data, each governing a different concern. Three are genuinely independent: bumping `DATA_REVISION`, `EXTRACTOR_VERSION`, or `ACTIVITY_CLASSIFIER_VERSION` triggers only its own re-derivation and invalidates no other cache. `PERSIST_VERSION` is NOT — it discards the catchup cache wholesale and forces a full re-scan, which reimports and so re-derives what the others govern. Bump it only for the reason below. **This guide deliberately does not pin each constant's current number — it changes often and drifts; read the live value and its changelog in the source file cited below.**

- **`DATA_REVISION`** (`src/main/collectors/engine/data-revision.ts`) — session-level re-derivation from source transcripts. Every session row is stamped `data_revision` at import; on boot `data-revision-rebuild.ts` re-parses each stale session and transactionally replaces its derived rows (events, agents, token_usage, session_artifact_links). Bump when parser/import semantics should re-derive already-imported sessions, and add a changelog entry to the revision-history comment. Sessions whose source transcript is gone are left untouched.
- **`EXTRACTOR_VERSION`** (`src/main/collectors/parsing/artifact-ref-extractor.ts`) — artifact-reference re-extraction. `session_artifact_links` rows carry `extractor_version`; `artifact-link-backfill.ts` re-runs the extractor on stale rows at boot. Bump when extraction semantics change (new artifact kinds, relation classification, patterns, confidence). Links are delete-then-reinsert, so refs the new version no longer emits drop out of every link-driven surface.
- **`ACTIVITY_CLASSIFIER_VERSION`** (`src/main/collectors/parsing/activity-segment-classifier.ts`) — activity-segment re-tiling for state-aware spend attribution (PRD-488). Each session's derivation is recorded in the `activity_segment_backfill_seen` high-water mark; `activity-segment-backfill.ts` re-tiles a session whose marker is stale or whose transcript mtime changed. Bump when phase taxonomy, idle-gap threshold, segment-boundary rules, or evidence-layer derivation change. The per-version history lives in that source file's header comment.
- **`PERSIST_VERSION`** (`src/main/collectors/engine/catchup-cache.ts`) — the file-level catchup cache (mtime/size fingerprints). Changing it invalidates the entire cache and forces one full re-scan of all transcript files on next boot. Bump for cache FORMAT/fingerprint changes only — parse-output changes are `DATA_REVISION`.

## Test Practices

Do not guard Desktop behavior by reading implementation source as text and regex/substring-matching it (`readSource`/`readFileSync` of a `src/**/*.ts(x)` file with `assert.match`/`.toContain`). Those guards break on every rename/reorder and can be satisfied by a comment. Use the right mechanism for the invariant:

- **Boundary / architecture invariants** — e.g. the boot graph (`src/main/index.ts`, `app.ts`, `window.ts`) must not statically import `src/main/database/**` or the design-system dashboard runtime (the SQLite/heavy-runtime boundary, see the Prisma section above), and the app-OTel runtime may only egress through the sanctioned relay transport — are enforced by **dependency-cruiser** (`scripts/dependency-cruiser.config.cjs`, run via `pnpm assert:design-system-boundary`), which resolves the real module graph (static value imports only) instead of scanning source text. Add or tighten a rule there rather than reintroducing a source-text scan. The retired `test/agent-dashboard-boundary.test.ts` also AST-checked two invariants dependency-cruiser cannot express — the `BrowserWindow` `webPreferences` lock (`contextIsolation: true`, no `nodeIntegration`, `sandbox: false`) and the preload↔handler `desktop:db` channel-parity contract. Neither is currently guarded; reinstate as a dedicated behavioral test (next bullet) if you need it, never by extending a deleted file.
- **Security / IPC gates** — allowlist enforcement before `shell.openExternal`, IPC handlers rejecting untrusted senders, disabled/live handler installation — are enforced by **behavioral tests** that invoke the handler/function and assert the effect. Follow `test/external-url-allowlist.test.ts` (`isAllowedExternalUrl` fail-closed policy), `test/desktop-session-manager.test.ts` (allowlist stubs `openExternal` and asserts it is not called), `test/ipc-profile-channels.test.ts` (a fake `handle` registrar + `isTrustedSender: () => false` proves handlers reject untrusted senders), and `test/agent-dashboard-disabled-ipc.test.ts` (disabled/branch responder installation). When an inline `app.ts`/`window.ts` handler cannot be reached without booting Electron, extract its registration into a testable function (mirroring `registerProfileConfigIpcHandlers`) rather than pinning it with a source regex.
- **Renderer wiring** — a component subscribes to an IPC event or invokes a `window.desktopApi` method — is enforced by a **vitest render test** (`src/renderer/**/__tests__/*.test.tsx`, run by `pnpm test:renderer`): mount the component with a stubbed `window.desktopApi`, dispatch the event / click the control, and assert the call. See `src/renderer/components/diagnostics/__tests__/logs-panel.test.tsx`, `src/renderer/components/__tests__/update-banner.test.tsx`, and `src/renderer/components/settings/__tests__/settings-panel-security-api-key.test.tsx`.

Reading declarative config/data (workflow YAML, `migration.sql`, JSON fixtures) is not source-text testing and remains allowed. See the root `AGENTS.md` "Test Practices" rules for the repo-wide statement.

Suite-level conventions — grandfathered test files being shrink-only, the E2E-through-the-real-boundary requirement, the spec-load import hazard, and the moved-code stale-import trap — live in **[`test/AGENTS.md`](test/AGENTS.md)**.

## Validation

For Desktop changes, run the narrow Desktop command first while iterating, then include the relevant tests, typecheck, and lint coverage for the touched monorepo surfaces. Use Desktop build/package validation only when the change specifically touches Desktop build output, workspace package materialization, packaging paths, or release payload behavior.

### `test:node` determinism (FEA-2399)

The `test:node` slice must be deterministic — the `desktop` CI check gates on it, and a single flaky assertion reddens the whole job (the runner has no retry/quarantine). When a node test waits for async work to complete, **synchronize on a real completion signal** emitted by the code under test (e.g. resolve a `deferred()` from an injected callback/mock when the awaited effect lands), not on a bounded poll loop. If a poll loop is genuinely unavoidable, it MUST `throw` when its bound is exhausted — never fall through silently and let a later assertion see stale state. This is enforced pre-merge by `test/no-silent-poll-barrier.guard.test.ts`.

To reproduce non-determinism, stress-run a suite: `STRESS_ITERS=100 STRESS_FILE=test/ingest-orchestrator.test.ts pnpm --filter desktop test:node:stress` (exits non-zero on the first failing iteration). ### Electron E2E: isolate `CODEX_HOME`

When running Desktop Electron E2E tests locally, set `CODEX_HOME` to a fresh temporary directory unless the scenario explicitly needs the operator's real Codex history. The Desktop importer reads local Codex sessions; using the real home directory can pollute list views and cause false failures such as seeded Sessions rows being paginated off the first page.
