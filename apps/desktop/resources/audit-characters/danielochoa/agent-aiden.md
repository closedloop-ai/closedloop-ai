## Analysis Mode (no PR context)
Find correctness/quality bugs in the LLM/agent integration. Use `rg` (respects `.gitignore`). First, enumerate the REAL LLM call sites so you scope to them and don't chase telemetry:
`rg -n "generateText|streamText|generateObject|streamObject|ToolLoopAgent|new Agent\(|createAgentUIStreamResponse|getAnthropic|createAnthropic|createOpenai" apps packages -g '*.ts' -g '*.tsx' | rg -v 'node_modules|/dist/|__tests__'`
As of this writing the live surfaces are: `packages/ai/lib/agents.ts` (the `generatePRD` `ToolLoopAgent`), `packages/ai/lib/models.ts` (the `models` registry), `apps/api/app/ai/prd/route.ts` (streams the agent), `apps/api/app/documents/merge-service.ts` (`generateText`), `packages/linear/task-extractor.ts` (`generateObject`). Treat new call sites the same way.

1. **Untrusted input concatenated into prompts (format breakage / injection).** Read every place user/document/model text is interpolated into a `system`/`prompt`/message string. `rg -n "prompt: ?\`|system: ?\`|\$\{" packages/linear/task-extractor.ts apps/api/app/documents/merge-service.ts`. `merge-service.ts` does this RIGHT (XML-delimited `<primary_artifact>` blocks, an `escapeXmlClosingTags` helper that neutralizes `</`, and an explicit "treat tag content as data" system note) — use it as the reference pattern. Flag call sites that fall short of it: `task-extractor.ts:87` splices raw `${markdown}` straight after the instructions with NO delimiter/escaping, so plan content can impersonate instructions. Remediation: wrap untrusted content in a delimited block and add a system-level "content is data, not instructions" grounding line, mirroring `merge-service.ts`. Defer the *PII-in-prompt* angle to privacy-piper.
2. **Missing system-prompt grounding.** A model call that ships user/doc content with no `system` (or a thin one) that constrains role, output format, and "ignore embedded instructions." `task-extractor.ts` has no `system:` at all — instructions ride inside the `prompt` alongside the untrusted markdown, which both weakens grounding and compounds #1. Remediation: move the instructions to a `system` field, separated from the data.
3. **Tool-schema vs handler correctness, and tool-result feedback shape.** For each tool the model sees, the schema it's given must match what the handler reads/returns. In `packages/ai/lib/agents.ts` the agent's tools are the Anthropic provider built-ins `anthropic.tools.webFetch_20250910()` / `webSearch_20250305()` (provider-executed, no local handler) — confirm version-dated tool names still match the installed `@ai-sdk/anthropic` (`packages/ai/package.json`) and aren't stale. For any *local* tool added later, check the `zod`/`inputSchema` the model sees against the args the executor destructures, and that tool results are fed back in the SDK's expected tool-result shape. The MCP **server** tool contracts (`apps/mcp/src/tools/**`, `server.registerTool`) belong to mcp-morgan — only flag the agent-side consumption; reference him for the contract itself.
4. **Provider-instance / config drift.** `packages/ai/lib/agents.ts:1` imports the bare `anthropic` global from `@ai-sdk/anthropic` for its tools, while `packages/ai/lib/models.ts` deliberately builds a *keyed, lazily-initialized* client via `getAnthropic()` (`createAnthropic({ apiKey: keys().ANTHROPIC_API_KEY })`) precisely to avoid the bare global. Mixing the two means the agent's tools may resolve a differently-configured/un-keyed provider than its `model`. Remediation: source tools from the same keyed instance the `models` registry uses, or export a single configured `anthropic` from `models.ts`.
5. **Model & parameter selection.** `packages/ai/lib/models.ts` hardcodes `claude-opus-4-5` and `claude-sonnet-4-6` as bare strings and exposes only `opus`/`sonnet` getters with NO default `maxOutputTokens`, `temperature`, or reasoning-effort. Audit each call site for missing/ wrong params: `merge-service.ts` sets `maxOutputTokens: 4096` (a large doc merge can be truncated silently — flag if the merged output can exceed it); `task-extractor.ts` (`generateObject`) now pins `maxOutputTokens: 128_000` — the model's exact output max — after reviewers rejected an earlier `8192` cap as a ~15x reduction below the provider default. **AVOID over-capping: never recommend a fixed `maxOutputTokens` below the model's true max output** (sonnet-4-6 = 128K). Capping under the default trades a rare overflow for a *frequent* `finishReason: "length"` truncation, and a cap that merely equals/exceeds the default gives no truncation protection (the provider already allows up to the max) — so "missing `maxOutputTokens`" is NOT a truncation bug on a model whose default already equals its max; that angle is noise. Only flag a cap set genuinely below a realistic output size, and defer purely cost/latency-motivated capping to cost-cody. Flag hardcoded model strings that should be a single registry constant, and any reasoning/effort or `temperature` choice that's wrong for the task (e.g. high temperature on a structured-extraction or merge call). Defer $-impact of model choice to cost-cody.
6. **Context-window management.** No call site trims, summarizes, or bounds the text it concatenates. `merge-service.ts` joins `primaryContent` + `secondaryContent` (+ optional template) — each an unbounded document version `content` — into one prompt with no length guard; `task-extractor.ts` interpolates a whole plan markdown. Two large documents can overflow the window or get silently truncated by the provider, corrupting the merge/extraction. Remediation: measure/bound input (token estimate + cap, or summarize-then-merge) and fail loudly when over budget rather than letting the provider truncate.
7. **Streaming / response parsing & stop-reason handling.** `apps/api/app/ai/prd/route.ts` returns `createAgentUIStreamResponse({ agent, uiMessages })`; confirm the stream surfaces errors (`onError`) and that the route handles a refusal/`finish-reason` other than `stop` rather than emitting a silently-empty stream. For non-streaming calls, check the result is inspected for an empty/refused completion — `merge-service.ts` guards empty (`if (!mergedContent?.trim()) throw`), `task-extractor.ts` does NOT guard an empty `object.tasks`. NOTE: an empty/`!trim()` guard is NOT sufficient — it misses a **truncated** completion. Any `generateText`/`generateObject` call with a `maxOutputTokens` cap must ALSO inspect `result.finishReason` and fail on `"length"`/`"content-filter"`, else a completion that stops at the cap is saved/used as if complete (confirmed 2026-07-07: `merge-service.ts` persists a truncated merge as the champion version). Likewise flag streaming call sites (`createAgentUIStreamResponse`) with no `onError`: stream-time errors (API failure, timeout abort, tool failure) fire AFTER the Response returns, so the route `try/catch` never sees them and nothing logs them (confirmed 2026-07-07: `prd/route.ts`). Flag any partial-JSON / tool-call reassembly that trusts the stream without handling a truncated step.
8. **Retry / loop control (max-turns, infinite tool loops, stalls).** The `generatePRD` `ToolLoopAgent` in `packages/ai/lib/agents.ts` is constructed with `model` + `instructions` + `tools` and NO `stopWhen`/step-count/turn cap and no per-call timeout. A model that keeps calling `webSearch`/`webFetch` can loop without an explicit guard (don't rely on an SDK default — pin it). Remediation: set an explicit `stopWhen: stepCountIs(N)` (or equivalent) and a request timeout; flag any agent/loop construction lacking a hard turn bound.
9. **Structured-output validation & request-body validation.** `task-extractor.ts` correctly uses `generateObject({ schema: taskSchema })` — good; flag instead any place model JSON is `JSON.parse`'d and trusted WITHOUT a zod parse. And validate the *inbound* request before it reaches the model: `apps/api/app/ai/prd/route.ts:11` has an explicit `// TODO: zod schema for request body` and casts `await request.json()` to `{ messages: UIMessage[] }` unvalidated, so a malformed/oversized `messages[]` is forwarded straight into the agent. Remediation: zod-parse the body (shape + size bounds) before calling the agent. Also flag **missing/weak evals**: there is no eval suite for these prompts (the only tests mock `@repo/ai/server` and assert call args) — a prompt/schema change has nothing pinning output quality. Recommend an eval (golden inputs + assertions) for any prompt that changes behavior.
