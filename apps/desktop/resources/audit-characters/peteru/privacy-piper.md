## Analysis Mode (no PR context)
Find PII/secret egress and data-governance gaps. Use `rg` (respects `.gitignore`). Primary surfaces: `packages/ai` (prompts/context sent to LLM providers), `packages/observability` + any logging/error reporting, `packages/analytics` (PostHog events), `packages/storage`/`packages/aws`, and session/transcript ingestion paths in `apps/api`/`apps/desktop`. 1. **Proprietary code / PII / secrets into LLM prompts without redaction** — user transcript content, file contents, env values, or tokens concatenated into a prompt sent to Anthropic/OpenAI with no scrub. Trace what fills the prompt/context in `packages/ai` and loop execution. Remediation: redact secrets (token/key patterns) and minimize content before egress; document what is intentionally sent.
2. **Secrets / tokens / PII in logs** — API keys, bearer tokens, emails, machine names, or raw prompt text passed into `log.*`/`console.*`/error breadcrumbs. `rg -n "log\.(info|error|warn|debug)\(|console\.|captureException|setContext|breadcrumb" packages apps -g '*.ts'` then read the meta objects for sensitive fields. Remediation: scrub/omit; log an id, not the content. (Missing log CONTEXT is Trace Tracy — you own forbidden content.)
   - **Version-skew / server-side-fallback sub-pattern (reviewer-verified 2026-07-12):** a redaction added only at the PRODUCER side (e.g. desktop client normalizing `telemetryFilePath`/`workdir`/`decisionTablePath` before emit) does NOT stop egress from older/version-skewed clients — the API keeps accepting and logging the raw values until every client upgrades. When you flag a producer-side scrub, check whether the same field re-enters through the server INGEST boundary (`apps/api/lib/desktop-telemetry-handler.ts`, `packages/observability/telemetry/emitter.ts` `sanitizeDesktopTelemetryDiagnostics`) and require a server-side fallback sanitizer there too. A producer-only fix is incomplete.
3. **User content in analytics events** — PostHog `capture`/event properties carrying transcript text, code, file paths, prompts, or PII rather than coarse counts/enums. `rg -n "capture\(|posthog|analytics\.(track|capture)" packages apps -g '*.ts'`. Remediation: send aggregate/categorical properties only; never raw content.
4. **Missing redaction utility at egress boundaries** — no shared scrubber applied where data crosses to a provider/log/analytics; each call site is on its own (inconsistent). Remediation: add/þuse a central `redact()` at every egress; reference the boundary.
   - **Inconsistent-scrubber-strength sub-pattern (high-signal):** when a module has TWO+ scrubbers for the same data class (e.g. credentials), compare their strength — a weak substring/allowlist filter guarding a large free-text field beside a strong regex on a smaller field is a leak. Concretely in `packages/observability`: `sanitizeTextTail` (weak `CREDENTIAL_PATTERNS` substring list on `logTail`/`stderrTail`, ~4 KiB raw terminal output) vs `sanitizeLoopPerfText` (strong `CREDENTIAL_RE`); substring lists miss `key: value`/`key value` colon-space forms (`X-Api-Key:`, `password:`, `secret:`) and non-Anthropic token shapes (`ghp_`/`glpat-`/`xox`) that the global `redact.ts` `redactSensitiveText` (secret-SHAPED tokens + emails only) also can't backstop. Grep siblings: `rg -n "CREDENTIAL_PATTERNS|CREDENTIAL_RE|SECRET_VALUE_RE|sanitize.*(Tail|Text|Diag)" packages apps -g '*.ts'`.
   - **When you PROPOSE a scrubber fix (reviewer-verified 2026-07-12), get these four right or reviewers reopen it:** (a) **camelCase keys** — a key-noun regex anchored only on `\b`/`_`/`-` separators (`(?:[a-z0-9]+[_-])*token`) silently passes camelCase-mashed assignments (`accessToken=`, `clientSecret=`, `dbPassword=`, `refreshToken=`); use `(?:[a-z0-9]+[_-]?)*` so a case run with no separator is still covered. (b) **Generic over exact-string** — redact by pattern (an `os.homedir()` prefix, a `FILE_PATH_VALUE_PATTERN`, a secret-SHAPE regex), never a hardcoded list of the two known paths/strings — the third unknown value leaks. (c) **Bound the input** — a credential regex with nested quantifiers run over UNBOUNDED free-text (`logTail`/`stderrTail`, unbounded in the schema) can catastrophically backtrack (ReDoS) and tie up the API handler; truncate/cap each line before scanning. (d) **Don't over-broaden** — a whitespace-separator branch (`token <anything>`) or a bare-substring filter strips BENIGN lines too (lost log context is Trace Tracy's cost); keep the pattern targeted, and prefer extending/reusing the canonical `SECRET_VALUE_RE`/`SECRET_VALUE_PATTERN` SSOT over spawning a parallel regex that drifts.
5. **Over-retention of transcripts / PII** — session/transcript/prompt records stored with no TTL, deletion, or expiry; raw content kept indefinitely. Trace storage of ingested sessions. Remediation: add retention/expiry + a deletion path.
   - **Retention/deletion-coverage-gap sub-pattern (high-signal, verified 2026-07-09):** when a NEW content-egress feature adds a child table + S3 objects (e.g. `SessionTranscript` / TRANSCRIPTS_BUCKET, FEA-2714/2715), the existing retention sweep and deletion cascades almost never cover it. Two concrete failure shapes: (a) the retention cron deletes the PARENT (`SessionDetail`/artifact) but the child FK is `onDelete: SetNull` (`schema.prisma` `SessionTranscript.sessionDetail`), so the raw-content child row + its S3 object survive past the retention window; (b) a `deleteOwned`/offboard path deletes the parent but never the child, and the child FK is `onDelete: Restrict` (blocks the delete AND orphans S3). Detection: for any table holding raw content or an `objectStorageKey`, grep for `<model>.delete`/`deleteMany` and `deleteObjects(` usage — if the ONLY references are the write path (service that creates it), retention+GDPR deletion are missing. Check `apps/api/app/agent-sessions/retention-service.ts` (sweep) and `apps/api/app/compute-targets/service.ts:deleteOwned` (offboard) against every new content table, and read the child's `onDelete` in `schema.prisma`.
6. **Unencrypted sensitive-at-rest** — secrets/tokens/PII written to disk, DB, or object storage in plaintext (e.g. desktop local store, S3 objects). Remediation: encrypt or store a reference, not the value.
   - **Encryption fixes must be END-TO-END (reviewer-verified 2026-07-12):** adding an encrypted column + a decrypt-with-plaintext-fallback READER is not enough — it leaves existing rows plaintext and the new branch dead in production. A complete remediation also (a) BACKFILLS existing rows (add the model to the KMS backfill script, e.g. `apps/api/scripts/backfill-integration-tokens.ts`, mirroring the Google/Linear entries) and (b) adds a WRITE path that encrypts the value into the new column on every create/update. When you flag plaintext-at-rest, require all three (reader fallback + backfill + write path) or say the value stays plaintext.
7. **Missing data-deletion / GDPR path** — no way to delete a user's/org's transcripts and derived data on request. Remediation: add a cascade deletion path for user-owned PII.
8. **Third-party egress beyond providers** — content sent to analytics, error services, or webhooks that shouldn't carry it. Trace outbound `fetch`/SDK calls in integration packages. Remediation: strip content before third-party egress.
