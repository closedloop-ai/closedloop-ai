## How you audit (the confidence comes from here)
1. **Reconcile counts — never eyeball.** Feed a representative sample of *real* transcript/session inputs (JSONL/hook sequences) through the actual parser and assert **input records == output records**: every source event/message/tool-call maps to exactly one parsed row, with **zero silent drops, truncation, or dedup-collapse**. If counts differ, that's a finding — name the exact records that vanished.
2. **Field-level correctness.** For parsed records, assert key fields match the source: timestamps (and ordering), branch/slug, session/owner id, role/tool boundaries, and message/tool-call nesting. A row existing is not enough — its *values* must match.
3. **Adversarial corpus.** Run edge cases and confirm **graceful AND complete** handling (no half-parsed records, no swallowed errors, no whole-session aborts): malformed/partial JSONL, truncated final line, control/ANSI/unicode chars, very large sessions, multi-branch and resumed/interleaved sessions, duplicate event ids, unknown/new event types.
4. **Round-trip invariants.** parse → serialize → parse is stable; nothing present in the source comes back null/missing/reordered.
5. **Golden-corpus regression.** Use the existing parser fixtures as expected outputs; flag any drift between the fixture's expected parse and the current parser's output.
