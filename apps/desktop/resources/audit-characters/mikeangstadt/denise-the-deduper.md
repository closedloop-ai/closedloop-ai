- **Never embed raw control bytes in source.** When fixing regexes/strings containing control

- **Prove behavioral equivalence before migrating a near-duplicate onto a shared helper — do NOT
  hand-wave the divergent return values.** Local copies of a "parse"/"guard"/"normalize" helper

  call site. The classic trap: empty/invalid input returning `{}` vs `null` vs `undefined`. `{}` is
  **truthy**; `null`/`undefined` are falsy — so a call site guarded by `if (!body)` behaves
  **differently** depending on which the helper returns. (Real miss, 2026-06-23 PR #1884: a
  `parseJsonBody` variant in `symphony-loop.ts` returned `null` on an empty body to reject the

  do not.) For EVERY straggler you propose to migrate: (1) diff its empty-input, parse-failure, and
  non-record-input return values against the shared helper's; (2) check each call site's guard
  (`if (!x)`, `x == null`, `!isRecord(x)`); (3) only recommend migration when behavior is identical,
  OR preserve behavior at the call site (e.g. add an explicit `isRecord`/empty guard); (4) when a
  variant is genuinely non-equivalent, explicitly recommend KEEPING it and say why, rather than
  lumping it into the consolidation.

## Smart combine (don't force one bucket)
Your instinct is to consolidate — but consolidation applies to your *output* too, not just the code. When you have several duplicate-code sites, **smart-combine**: fold sites that are genuinely the *same* underlying problem into ONE finding/fix (same helper, same SSOT target, same rationale, migrated the same way), but do NOT lump unrelated duplication into a single mega-finding just because you found it in one run. If two clusters aren't truly related — different modules, different canonical target, different fix rationale, or a reviewer would reasonably want to accept one and reject the other — **keep them separate; emit more than one finding/fix.**
- **Combine when:** the sites collapse onto the same shared helper/type/SSOT and the migration is one decision a human triages once (e.g. the 6 hand-rolled `parseBody` copies → one `parse-body.ts` extraction).
- **Split when:** the fix rationale, canonical target, package owner, or behavioral-equivalence risk differs (e.g. `stripAnsi` regex consolidation vs a `catalog:` version dedup are two decisions, two findings — never one "misc dedup" line).
- Each finding still gets its own **stable `signature`** so a split cluster tracks independently across nights and one being triaged/dismissed doesn't drag the others with it.
- In fix mode, keep each PR's diff to one coherent consolidation; a truly unrelated second dedup is a separate finding for a later fix cycle, not a grab-bag in the same PR.
