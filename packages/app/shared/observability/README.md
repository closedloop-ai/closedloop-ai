# Product click analytics

Each root surface adapter (web, Desktop, marketing) installs one capture listener for `button_clicked`. Canonical page names are emitted; paths and route IDs stay local. Page-view properties are reused only while they belong to the current page. Desktop preserves dashboard volume buckets, IPC contracts, identity enrichment, and best-effort transport.

Native and ARIA actions include portaled menus, options, tabs, and custom role buttons. Capture preserves the source page and label before activation. Radix press/keyboard events are deduplicated against clicks; Select typeahead and cmdk text editing/IME confirmation do not count as activation. Custom clickable rows use `data-analytics-action`; custom keyboard handlers without a semantic role also declare `data-analytics-keyboard`.

`button_name` uses normalized visible copy, then accessible label, then tooltip for icon-only controls. The shared build transform in `scripts/analytics/` runs in Next Turbopack/Webpack and desktop Vite. It resolves product literals, imported constants, and closed static menus into control-local provenance attributes. There is no generated catalog to maintain: changing source copy changes the build output automatically. Mock/test files do not establish product provenance. Mutable or escaping object/array values fail closed to generic names; primitive literal exports remain supported.

A runtime label must match its own source-provenance channel. Unknown/customer expressions, mixed customer/product branches, and customer text that happens to equal product copy all use a generic action name. Wrappers that replace children clear inherited provenance; transparent forwarding preserves it. Static product punctuation such as slashes and domains remains intact. A static `data-analytics-label` selects a specific generic action for customer-content controls, for example `Select session`; never populate that property from customer data.

The compiler tests render transformed JSX, and each transport test supplies explicit provenance for its fixture controls. Production build fixtures exercise both compiler integrations. Existing dedicated analytics events continue unchanged.

The marketing adapter (`apps/web/components/marketing-surface-analytics-adapter.tsx`, ISS-12557) forwards through the root PostHog client, so capture-time `surface`/`environment` attribution, opt-out, and replay independence come from that client. It reads the page from `location` at activation (locale prefix stripped; every `/docs` page is `docs`), so it does not depend on a pageview. Controls compiled outside this repo's JSX transform carry no provenance and use generic names: Fumadocs chrome and MDX-rendered docs content, and the OpenAPI playground. The global error page (`apps/web/app/[locale]/global-error.tsx`) renders its own document in place of the root layout, so the adapter is not mounted there and its retry is not tracked. A label mapped from a list whose items also feed an attribute (`href={link.href}`) fails closed, so the header, mobile nav, and footer write their links out.
