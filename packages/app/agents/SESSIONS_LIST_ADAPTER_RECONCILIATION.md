### Fixture census and drift audit

- List fixture: canonical `SessionTableRow` builders, two named sessions, explicit issue/project reference maps, and stable permissions.
- Detail fixture: canonical `AgentSessionDetailFixture` builder selected by the current memory path; trace, timeline, comments, metadata, and properties remain fixture-backed.
- Navigation fixture: `/sessions` and `/sessions/:id` only, hosted by the existing memory adapter.
- Token overrides: none. The adapter and shell use design-system tokens and existing layout classes.
- Shared-source drift exemptions: none. A prototype-only value may live in the fixture module; no component or interaction implementation may remain forked.

### Replacement ledger

After the adapter tests pass, delete the Sessions-only shell and sidebar. Move the remaining legacy list/detail modules under their live `web-master` consumer, with no compatibility exports left at the old paths. The Sessions route keeps only its page, production-bound metadata, and import of `SessionsPrototypePreview`; Git history remains the archive for anything with no consumer.
